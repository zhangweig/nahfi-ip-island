# Grok Bot 额度请求（0.6.51）

针对“Grok Bot 原客户端正常、岛仔额度接口返回 403”的反馈，发现岛仔此前将随机请求 UUID 作为机器身份生成 `x-cursor-checksum`。请求标识并非客户端机器身份，这个头与公开参考实现不符。

0.6.51 移除此头，保留 `GetSandUsageStatus` Connect-RPC 的必要头及 `{}` 请求体。不收集、生成或复制原客户端机器指纹，也不修改原客户端登录文件。

参考：[ai-usagebar 的 Grok Bot usage_call](https://github.com/akitaonrails/ai-usagebar/blob/836a6e755190409cdb5cbc2d291bca5b6f18d5b7/src/grokbot/fetch.rs)，明确不发送无法可靠重现的机器校验头。这里核对了公开请求格式，没有复制其凭据或源码。

## 已验证和未验证

本地模拟服务端检查所有必需请求头、校验头缺失、请求体和成功额度解析；401/403 响应正文不会出现在界面或错误信息中。这些测试不证明真实用户账号已恢复。

原客户端能使用不等于其持久化登录文件、接口权限或网络出口一定与岛仔一致。若新版仍为 403，需要继续确认这些差异，不能仅凭 403 宣称账号失效、封禁或强制重新登录。

## 使用与代理

先退出旧版，运行新版，在 AI 额度设置中点“刷新额度”。当前账号和文件路径无需重建。

额度请求读取进程代理环境变量或 Windows 系统代理；IP Monitor 中填写的端口仅影响 IP 查询，不影响 AI 额度。若原客户端单独配置了代理，需要核对二者网络出口是否一致。

不要分享 auth.json、sand-secrets.json、Cookie、令牌或原始 HTTP 响应正文。

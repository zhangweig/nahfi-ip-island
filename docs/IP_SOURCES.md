# IP 数据源选择（0.6.52）

不存在在所有国家、代理出口和分流规则下都最好的单一服务。本项目只需展示请求出口的 IP、国家代码与国旗，因此采用轻量主源和独立备用源，而不是把网页首页猜成 API。

| 来源 | 用途与优点 | 限制 |
| --- | --- | --- |
| Cloudflare Trace（默认主源） | HTTPS、无 API Key、直接读取 `ip` 与国家 `loc` | 诊断端点，不是付费地理数据库或可用性承诺；部分网络可能不可达 |
| ipwho.is（自动模式备用） | 无需在程序内嵌入密钥、返回 IP 与国家名称 | 共享代理出口可能限流，服务条款和额度可能变化；遵从响应 Retry-After |

Cloudflare 官方端点说明：[Cloudflare-managed /cdn-cgi/](https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/)。该文档公开列出 `/cdn-cgi/trace` 诊断端点。字段协议也可见广泛使用的 trace 客户端解析，但不据此宣称全球访问或国家数据库准确率经过实测。

主源：`https://www.cloudflare.com/cdn-cgi/trace`
备用：`https://ipwho.is/`（[服务文档](https://ipwhois.io/documentation)）。

## 请求和隐私

- 主源成功不查询备用，减少网络请求和向额外服务暴露出口地址。
- 主备使用同一个配置快照：自动系统代理、系统路由/TUN 或指定本机代理。代理失败不会改走直连。
- 同一次结果的 IP、国家和来源来自同一个响应，不跨源拼接。
- `loc` 是访问者国家，`colo` 是 Cloudflare 数据中心，两者不混淆。
- Trace 的其余字段不持久化或显示；完整 IP 默认打码，显示和复制需主动操作。
- 429 会按 Retry-After 的秒数/日期冷却（限制在 5 秒至 7 天内）；没有可用值时使用 60 秒。冷却时可用另一源，手动锁定某源则不自动切换。
- 每源最多约 4 秒，主备共约 8 秒；代理或网卡变动时丢弃旧请求结果并重新检测。IP 页定期检查间隔最多 10 秒，限流仍遵从冷却。

数据源不同域名可能命中不同代理规则，因此结果只代表访问该源时的请求出口。全局和 TUN 使用相同出口时 IP 可以不变，程序不推测代理软件内部模式。

## 验证边界

已验证本地 HTTP 模拟响应解析、IPv4/IPv6、loc/colo 区分、主备切换、同一代理、限流冷却、错误正文脱敏、来源标记和配置持久化。

本次云环境没有应用新域名放行，未进行真实公网测速或用户代理/TUN 实机测试。已把两个服务域名添加到环境配置草稿；如需在此云环境实测，需要在环境设置保存并发布。文档和本地合约测试与公网可用性验证是分开的，不能把本地测试结果当成全球可用性保证。
